# Traceability Matrix Template

> 用途：把需求、规格、任务、测试、审计、修复和交付连成一条证据链。  
> 使用时复制到具体项目中，按真实内容填写。

## 1. 项目账本

| 字段 | 内容 |
|---|---|
| 项目名称 | `<项目名称>` |
| 项目版本 | `<版本>` |
| 当前主目标 | `<GOAL-###>` |
| 当前阶段 | `INBOX / CLARIFIED / PRD_READY / SPEC_READY / PLANNED / IN_PROGRESS / VERIFIED / REVIEWED / RELEASED / CRYSTALLIZED` |
| 负责人 | `<开发者/AI角色/团队>` |
| 最后更新 | `<日期>` |

## 2. 需求追踪

| REQ | 用户/场景 | 需求描述 | 来源 | 状态 | 版本 |
|---|---|---|---|---|---|
| `REQ-001` | `USER-001 / SCN-001` | `<原子需求>` | `<用户/文档/会议>` | `<状态>` | `<版本>` |

## 3. PRD/SPEC 映射

| REQ | PRD | SPEC | 验收指标 | 不做范围 |
|---|---|---|---|---|
| `REQ-001` | `PRD-001` | `SPEC-001` | `<指标>` | `<边界>` |

## 4. 任务与验证映射

| SPEC | TASK | 改动范围 | TEST | 验证命令 | 结果 |
|---|---|---|---|---|---|
| `SPEC-001` | `TASK-001` | `<文件/模块>` | `TEST-001` | `<命令>` | `<PASS/FAIL/未验证>` |

|---|---|---|---|---|---|
| `AUD-001` | `<问题>` | `P0/P1/P2/P3` | `<ID>` | `FIX-001` | `<状态>` |

| ADR/MEM | 类型 | 内容 | 影响范围 | 写入位置 |
|---|---|---|---|---|
| `ADR-001` | 架构决策 | `<决策>` | `<模块/流程>` | `<文件路径>` |

| `v0.1` | `<目标>` | `REQ-001, REQ-002` | `REQ-009` | `<通过哪些测试>` |

## 8. 变更影响分析

每次新增需求或改动需求时填写：

```text
变更 ID:
触发来源:
影响的 REQ:
影响的 PRD:
影响的 SPEC:
影响的 TASK:
影响的 TEST:
是否影响当前版本:
是否需要用户确认:
是否需要架构评审:
结论:
```

## 9. 完成定义

一个功能只有同时满足以下条件，才能标记完成：

- 需求有编号。
- PRD/SPEC 有对应条目。
- 代码或文档改动范围明确。
- 至少一个验证方式存在。
- 验证结果已记录。
- 审计问题已处理或明确暂缓。
- 需要长期记忆的决策已经沉淀。
