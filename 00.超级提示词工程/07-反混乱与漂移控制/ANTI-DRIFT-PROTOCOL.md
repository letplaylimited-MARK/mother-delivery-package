# Anti-Drift Protocol

> 用途：防止通用 AI 协同开发中出现降智、混乱、需求漂移、规格漂移、记忆污染和无休止重构。  
> 适用：任何持续超过一次会话、超过一个功能、或涉及多个文件夹/工具/模型的项目。

## 1. 反漂移总原则

```text
先冻结当前事实
再接收新增意图
再判断影响范围
再更新 PRD/SPEC/任务图
最后才执行
```

不要让“刚刚想到的新功能”直接进入代码。它必须先成为一个 `REQ`，再经过影响分析。

## 2. 三种漂移

| 漂移 | 定义 | 识别信号 | 控制动作 |
|---|---|---|---|
| 需求漂移 | 用户目标不断变化但文档未同步 | “顺便也加...”、“再帮我...” | 新建 REQ，做版本归属 |
| 规格漂移 | 代码实现偏离 PRD/SPEC | 测试补不上、说明说不清 | 暂停开发，更新 SPEC 或回退实现 |
| 语义漂移 | 同一个词在不同会话含义变化 | “母包/用户包/交付包”混用 | 维护术语表和边界定义 |

## 3. 任务进入规则

每个新需求先进入这个判断：

```text
这是 bug 修复吗？
  是 -> 是否 P0/P1？是则打断，不是进入队列
  否 -> 这是当前版本目标内吗？
      是 -> 新建 REQ 并做影响分析
      否 -> 放入未来版本队列
```

## 4. 变更影响分析

新增或修改需求前必须填写：

| 问题 | 说明 |
|---|---|
| 影响目标 | 会不会改变当前 `GOAL`？ |
| 影响用户 | 会不会改变目标用户或权限？ |
| 影响流程 | 会不会改变用户主流程？ |
| 影响数据 | 会不会改变数据结构、迁移、存储？ |
| 影响接口 | 会不会改变 API/MCP/CLI/文件契约？ |
| 影响测试 | 需要新增或修改哪些测试？ |
| 影响交付 | 是否影响用户交付包四体系？ |

若任一项为“是”，必须更新 PRD/SPEC/测试或明确暂缓。

## 5. 反幻觉证据规则

AI 输出事实时必须落入四类之一：

```text
[已读文件] 文件路径 + 摘要
[已运行] 命令 + 结果
[已推断] 推断依据 + 不确定性
[未验证] 为什么未验证 + 下一步验证方式
```

禁止输出：

- “应该已经支持”但没有文件或测试证据。
- “所有问题已解决”但没有验证命令。
- “最佳实践是”但没有说明当前项目是否适用。
- “可以直接重构”但没有改动半径和回退方式。

## 6. 反任务堆死机制

### WIP 限制

```text
主目标: 1
当前里程碑: 1
进行中任务: 最多 3
未审计完成项: 最多 5
```

超过限制时，AI 必须先帮助用户排序，而不是继续承诺更多任务。

### 停止线

出现以下任一情况，停止新增开发：

- 当前验证失败但还在继续加功能。
- PRD/SPEC 与代码明显不一致。
- 用户新增需求会改变架构边界。
- AI 无法说清正在做哪个 `REQ/TASK`。
- 已经连续两轮修复同一个问题但没有审计。

## 7. 反重构失控机制

重构必须先分类：

| 类型 | 是否允许直接做 | 要求 |
|---|---|---|
| 格式化/命名 | 可以 | 小范围、无行为变化 |
| 局部结构改善 | 可以 | 有测试或人工检查 |
| 跨模块重构 | 需要 SPEC | 写影响范围和回退 |
| 架构替换 | 需要 ADR | 需要沙盘与评审 |
| 删除旧能力 | 需要用户确认 | 明确迁移策略 |

## 8. 记忆写入规则

不要记录一切，只记录能帮助未来 AI 少犯错的内容。

| 优先级 | 写入条件 | 示例 |
|---|---|---|
| P0 | 包边界、不可违反规则、关键决策 | 母包给开发者，用户包给最终用户 |
| P1 | 架构选择、风险、验证结果 | Q-SpecTrum 是主集成层 |
| P2 | 普通任务进度 | 某文件已更新 |
| P3 | 临时想法 | 暂不写入长期记忆 |

长期记忆必须写入明确文件，不依赖聊天上下文。

## 9. 发布前一致性扫描

每次准备交付前至少检查：

```powershell
rg -n "TODO|待确认|未验证|临时|hardcode|硬编码" .
rg -n "<某台电脑|C:\\Users|D:/" .
```

再检查：

- README 是否与真实入口一致。
- PRD/SPEC 是否与功能一致。
- 运行命令是否可以复制执行。
- 用户交付包四体系是否同步。
- 审计问题是否有状态。

## 10. AI 自检短句

每次复杂任务开始前，AI 先回答：

```text
我当前处理的 GOAL/REQ/TASK 是什么？
我依据哪些文件而不是聊天印象？
我即将修改哪些路径？
我如何验证？
哪些内容只是推断？
```

如果答不上来，不能开始执行。
