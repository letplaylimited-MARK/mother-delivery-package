# Mother Pack AI Collaboration Blueprint

> 用途：定义母交付包如何成为“开发者 + 通用 AI 大模型”的协同开发操作系统。  
> 结论：母交付包不取代通用 AI，而是给通用 AI 提供上下文、边界、工具路由、证据链、记忆、沙盘、验证和交付结构。

## 1. 最佳总体方案

```text
00 超级提示词工程        = 控制平面：启动、路由、上下文、阶段门、反漂移
12 引导秘书逻辑          = 入口层：意图识别、置信度、澄清、分流、交接包
05 Q-SpecTrum           = 总脑运行层：角色、任务、技能、闭环、验证、记忆入口
03/02 Knowledge System  = 知识与记忆层：知识图谱、知识结晶、长期记忆、MCP 检索
01 Ghost Channel        = 状态与证据层：同步、审计、因果顺序、快照、回滚
04 QCM                  = 沙盘与涌现层：多角色共识、风险审计、SRS gate、飞轮
用户交付包              = 项目成果层：价值体系、功能体系、结构体系、运作体系
10 通用AI协作生态       = 接入契约：模型、Agent、Skill、LSP、MCP、插件、CI、评估
11 模型原生协作协议     = 兼容层：尊重模型自身系统逻辑，不越权、不污染、不覆盖
```

这套结构的目标不是让 AI 一次性读完整个母包，也不是用母包替代模型能力，而是让 AI 每次只读最小必要上下文，并且每个判断都有来源、每个任务都有编号、每个完成都有验证、每个结论都有沉淀。

## 1.1 通用 AI 协作生态

母包应协同的不只是一个聊天模型，而是一整组 AI 应用开发生态：

| 生态层 | 例子 | 母包职责 |
|---|---|---|
| 认知层 | 通用 AI 大模型、编码模型、本地模型、多模态模型 | 理解意图、推理方案、生成内容，但必须受证据链约束 |
| 角色层 | 产品、架构、开发、测试、审计、运维、UX、知识管理员 | 通过角色团队沙盘暴露盲点和完成评审 |
| 技能层 | Prompt Skill、需求拆解、技术选型、计划、验证、报告 | 进入能力注册表，按触发条件调用 |
| 工具层 | LSP、MCP、插件、Shell、浏览器、数据库、文档/表格工具 | 提供真实执行和事实证据 |
| 知识层 | RAG、向量库、重排、代码索引、知识图谱、长期记忆 | 防止重复解释、上下文丢失和旧报告误用 |
| 工程层 | Git、测试、lint、typecheck、CI/CD、依赖、安全扫描 | 把完成从“说了”变成“验证了” |
| 治理层 | PRD、SPEC、TASK、TEST、AUD、ADR、权限、密钥、发布门 | 控制漂移、越权、泄露和无休止重构 |
| 交付层 | 四体系、安装脚本、验证脚本、CHANGELOG、版本包、反馈闭环 | 把开发成果变成用户可用成果 |

所有新能力都应按 `10-通用AI协作生态/AI-CAPABILITY-INTEGRATION-CONTRACT.md` 接入。

## 1.2 不覆盖模型系统逻辑

母包要成为通用 AI 的最强辅助，必须遵守一个硬边界：

```text
模型自身系统规则 > 当前平台/工具规则 > 用户请求 > 母包文档 > 历史记录
```

因此，母包中的提示词、角色、协议和工作流只提供项目内协作结构，不能要求任何模型忽略自身系统规则、安全规则、工具规则或权限边界。跨模型交接时，应先读取 `11-模型原生协作协议/MODEL-NATIVE-COLLABORATION-PROTOCOL.md`。

## 3. 标准数据工作流

```text
用户自然语言
  -> 00/12 Guide Secretary: 意图识别、置信度、澄清、分流、交接包
  -> 00 Intake: 澄清目标、边界、验收
  -> 00 Atomic: 生成 GOAL/REQ/PRD/SPEC/TASK/TEST ID
  -> 05 Router: Secretary 分配 TRUM/SPEC/QCM 角色
  -> 03 Retrieval: 搜索既有知识、旧决策、相关规格
  -> 04 Sandbox: 多角色沙盘、风险审计、SRS gate
  -> 05 Execute: 任务执行、Skill/MCP/LSP/插件协作
  -> 10 Contract: 检查模型/Agent/Skill/工具的输入、输出、权限、证据
  -> 01 Evidence: 记录状态差异、审计、快照、同步结果
  -> Verify: 测试、脚本、人工验收、发布门
  -> 03/05 Memory: 知识结晶、ADR、长期记忆
  -> User Delivery: 更新价值/功能/结构/运作四体系
```

## 4. 六个闭环

| 闭环 | 入口 | 出口 | 防止的问题 |
|---|---|---|---|
| 需求闭环 | 用户想法 | REQ + PRD + 验收指标 | 需求漂移 |
| 规格闭环 | PRD | SPEC + TEST | 规格漂移 |
| 执行闭环 | TASK | diff + 验证结果 | 任务堆死 |
| 审计闭环 | 实现结果 | AUD + FIX | 幻觉完成 |
| 记忆闭环 | 决策/经验 | ADR + MEM + 知识图谱 | 跨会话遗忘 |
| 交付闭环 | 可运行项目 | 用户交付包四体系 | 交付不可用 |

## 5. 强制阶段门

### Gate 0：上下文门

AI 必须先说明：

```text
我在哪个包：母交付包 / 用户交付包 / 子系统？
我处理哪个 GOAL/REQ/TASK？
我依据哪些文件？
我不应该碰哪些目录？
```

### Gate 1：需求门

没有以下内容，不能进入开发：

```text
目标用户
问题场景
成功指标
不做范围
当前版本归属
```

### Gate 2：规格门

没有以下内容，不能开始实现：

```text
模块影响
接口/数据影响
配置/依赖影响
验证方式
回退策略
```

### Gate 3：发布门

没有以下内容，不能说“完成”：

```text
验证命令或人工验收记录
审计问题状态
本机路径与密钥扫描
PRD/SPEC/TEST 同步状态
交接与长期记忆更新
```

## 6. 统一状态对象

```yaml
id: TASK-20260525-001

```

这个对象可以先以 Markdown/YAML 方式落地，后续再接入 Ghost Channel Schema、03 MCP、05 DB 或 QCM 评分。

## 7. 与通用 AI 大模型的协作方式

通用 AI 每次进入项目时，不要求它“记住一切”，而要求它执行固定协议：

1. 读 `AI_PROJECT_CONTEXT.md`。
2. 读 `00.超级提示词工程/README.md`。
3. 读 `00.超级提示词工程/11-模型原生协作协议/MODEL-NATIVE-COLLABORATION-PROTOCOL.md`，确认母包不覆盖模型系统逻辑。
4. 读 `00.超级提示词工程/12-引导秘书逻辑/GUIDE-SECRETARY-PROTOCOL.md`，先输出意图、置信度、路由和交接包。
5. 按路由矩阵选择子系统。
6. 生成 Context Pack。
7. 若是持续开发，先读取追踪矩阵和交接摘要。
8. 若是复杂任务，启动 AI 角色团队沙盘。
9. 执行前声明改动半径和验证方式。
10. 执行后写验证、审计、交接、记忆。

## 8. 最小落地路线

### Phase 0：已建立

- 00 控制平面骨架。
- 12 引导秘书入口协议。
- 用户交付包四体系模板。
- 母包/用户包边界。
- 原子化治理、反漂移协议、角色沙盘文档。

### Phase 1：下一步应做

```text
PROJECT_REGISTRY.yaml
CAPABILITY_REGISTRY.yaml
ARTIFACT_REGISTRY.yaml
VALIDATION_REGISTRY.yaml
TRACEABILITY-MATRIX.md
```

这些注册表先以静态文件存在，避免一开始就做复杂系统。

### Phase 2：工具化

- 用脚本生成 Context Pack。
- 用脚本扫描本机路径、密钥、未验证标记。
- 用 03 MCP 查询需求/规格/记忆。
- 用 05 TaskManager 管理任务状态。

### Phase 3：状态总线

- 将 `REQ/SPEC/TASK/TEST/AUD/MEM` 映射到 Ghost Channel 结构。
- 用 Vector Clock 记录多 AI 修改顺序。
- 用 AuditEntry 记录验证与评审。
- 用 Snapshot 支持阶段回滚。

### Phase 4：沙盘评分

- 用 QCM 沙盘检查复杂任务。
- 用 SRS gate 决定是否进入实现。
- 用飞轮记录“需求 -> 验证 -> 记忆”的改进循环。

### Phase 5：交付自动化

- 从追踪矩阵生成用户交付包四体系草案。
- 运行交付验证。
- 清理研究噪音、个人路径、密钥。
- 压缩用户交付包。

## 9. 不做清单

- 不让 AI 一次性吞完整母包。
- 不把旧报告当当前事实。
- 不把 QCM 演示数值当真实项目成功证明。
- 不把 Ghost Channel 当前文档能力等同于已经接入主管线。
- 不把用户新增想法直接塞进当前开发任务。
- 不把交付包变成母包的压缩副本。

## 10. 成功指标

| 指标 | 目标 |
|---|---|
| 需求追踪率 | 每个当前版本需求都有 `REQ` |
| 规格覆盖率 | 每个开发中需求都有 `SPEC` |
| 验证覆盖率 | 每个完成任务都有验证记录或明确未验证 |
| 审计关闭率 | P0/P1 审计问题交付前为 0 |
| 记忆沉淀率 | 每个重大决策都有 ADR/MEM |
| 路径安全 | 交付前本机绝对路径扫描无命中 |
| AI 可接手性 | 新 AI 读取入口文档后能说明当前状态、下一步、风险 |
