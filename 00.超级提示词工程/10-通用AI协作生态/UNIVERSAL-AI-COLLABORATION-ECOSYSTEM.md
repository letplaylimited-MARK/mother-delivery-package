# Universal AI Collaboration Ecosystem

> 用途：补全母交付包需要协同的通用 AI 大模型生态组件。  
> 核心原则：母交付包不取代任何通用 AI 大模型，而是为模型、智能体、工具、插件、工作流、知识和交付提供统一协作底座。

## 1. 定位

母交付包应该像一个“AI 协作操作台”：

```text
通用 AI 大模型负责理解、推理、生成和协商
母交付包负责上下文、边界、工具路由、证据链、记忆、审计、交付
外部工具负责真实执行、真实检索、真实验证、真实发布
```

它不是一个封闭系统，而是一个可接入多模型、多智能体、多工具、多工作流的开放协作层。

## 2. 需要纳入的生态组件

| 组件族 | 典型成员 | 母包如何协同 |
|---|---|---|
| 通用 AI 大模型 | ChatGPT、Claude、Gemini、通义、文心、DeepSeek、本地模型 | 读取 Context Pack，按阶段门执行，不凭聊天记忆越权 |
| 编码智能体 | Codex、Cursor Agent、OpenCode、Claude Code、Copilot Agent | 执行代码任务，必须绑定 TASK/SPEC/TEST |
| 角色智能体 | 产品、架构、开发、测试、审计、运维、数据、UX、发布、知识管理员 | 通过角色团队沙盘参与决策和评审 |
| Skill/技能 | 提示词工程、需求拆解、技术选型、计划、验证、文档生成 | 进入能力注册表，声明触发词、输入、输出、验证 |
| 工作流引擎 | SOP、状态机、任务看板、自动化流水线、定时任务 | 承载 Intake -> Verify -> Memory 的流程 |
| LSP/代码语义 | 语言服务器、类型检查、跳转、引用、诊断、重构 | 提供代码事实，避免 AI 只靠文本猜测 |
| MCP 工具 | 文件、数据库、知识库、搜索、浏览器、项目管理、外部 API | 作为可调用工具层，必须有权限和失败处理 |
| 插件/连接器 | 浏览器、Chrome、文档、表格、演示、GitHub、云盘、Issue 系统 | 接入外部系统，输出必须写入证据记录 |
| RAG/检索 | 全文搜索、向量库、重排、代码索引、文档索引 | 给模型补事实，不把旧上下文当权威 |
| 知识图谱 | 需求-模块-接口-测试-风险-决策关系图 | 追踪项目结构和影响范围 |
| 长期记忆 | 用户偏好、架构决策、风险、经验、交接摘要 | 只写 P0/P1，避免记忆污染 |
| 测试系统 | 单元、集成、E2E、回归、性能、可访问性、兼容性 | 完成证据的主要来源 |
| CI/CD | 构建、测试、打包、发布、回滚 | 自动化验证和交付门 |
| 安全与合规 | Secret 扫描、依赖扫描、权限、隐私、License、SBOM | 防止交付泄露和合规风险 |
| 观测系统 | 日志、指标、trace、错误报告、用户反馈 | 运行后继续学习和修复 |
| 评估系统 | Prompt eval、模型 eval、任务成功率、幻觉率、审计通过率 | 评估 AI 协作质量 |
| 交付系统 | README、四体系、安装脚本、验证脚本、CHANGELOG、版本包 | 把开发成果转成最终用户可用成果 |

## 3. 补充的关键能力

除了用户已提到的智能体、技能、工作流、LSP、MCP、插件、角色、系统，还需要补上：

- **模型路由**：不同任务选择不同模型或本地模型，记录为什么选择。
- **模型降级**：主模型失败、超时或成本过高时，切换备用模型。
- **嵌入与重排**：用于知识检索、代码搜索、相似需求查找。
- **代码索引**：函数、类、接口、依赖、引用关系。
- **Schema 注册**：让 AI 输出结构化对象，减少自由文本误读。
- **权限模型**：只读、可写、可执行、可发布分级。
- **密钥管理**：真实密钥不进交付包，不进长期记忆。
- **环境封装**：虚拟环境、容器、devcontainer、依赖锁定。
- **迁移系统**：数据库迁移、配置迁移、版本升级。
- **回滚机制**：Git、快照、备份、发布回滚。
- **Issue/Backlog**：需求、缺陷、技术债、未来版本队列。
- **ADR 决策记录**：记录为什么这样做，不只记录做了什么。
- **Release 管理**：版本号、CHANGELOG、发布说明、验收签核。
- **用户反馈闭环**：最终用户反馈重新进入 REQ/AUD/FIX。
- **成本与性能预算**：模型调用、运行时间、资源消耗、延迟目标。
- **数据治理**：数据来源、可用性、脱敏、保留周期、删除策略。
- **人类确认门**：高风险操作必须由开发者或用户确认。

## 4. 协作原则

### 4.1 通用 AI 是主认知层

通用 AI 大模型负责：

- 理解自然语言。
- 推理需求和方案。
- 生成文档、代码、测试、计划。
- 解释复杂系统。
- 与用户协商取舍。

母交付包不替代这些能力，只负责让这些能力被正确约束和放大。

### 4.2 工具是事实层

工具负责：

- 文件是否存在。
- 代码是否编译。
- 测试是否通过。
- 搜索结果是什么。
- 数据库里有什么。
- 页面是否可打开。

AI 不能用想象替代工具事实。

### 4.3 文档是长期状态层

文档负责：

- PRD/SPEC/TASK/TEST/AUD/MEM。
- 跨会话交接。
- 架构决策。
- 交付说明。
- 风险与边界。

聊天内容不能当长期状态。

## 5. 标准接入检查

任何新智能体、Skill、MCP、插件、工作流接入母包前，必须回答：

```text
名称:
能力:
适用任务:
输入:
输出:
读取权限:
写入权限:
执行权限:
依赖:
失败模式:
验证方式:
证据记录:
是否可进入用户交付包:
```

未回答这些问题的能力，只能作为实验能力，不能进入正式开发流程。

## 6. 推荐协作拓扑

```text
通用 AI 大模型
  -> 00 控制平面
      -> Context Pack
      -> Capability Registry
      -> Stage Gate
  -> 05 总脑/角色/任务
      -> Agent/Skill/Workflow
  -> 03/02 知识/RAG/记忆
      -> Search/Vector/Graph/Memory
  -> LSP/MCP/Plugins
      -> Code/File/DB/Browser/Docs/API
  -> Test/CI/Security/Eval
      -> Evidence
  -> 用户交付包
      -> Value/Function/Structure/Operation
```

## 7. 成熟度等级

| 等级 | 状态 | 可用范围 |
|---|---|---|
| L0 想法 | 只有概念 | 不能接入任务 |
| L1 提示词 | 有使用说明 | 可用于人工辅助 |
| L2 模板 | 有输入输出模板 | 可用于文档/规划 |
| L3 工具 | 可运行命令或 MCP/API | 可用于开发任务 |
| L4 验证 | 有测试和失败处理 | 可用于关键路径 |
| L5 交付 | 可迁移、可审计、可回滚 | 可进入用户交付包 |

## 8. 最重要的约束

```text
AI 可以提出方案，但不能伪造事实。
工具可以执行任务，但不能决定产品方向。
记忆可以帮助延续，但不能替代当前验证。
插件可以扩展能力，但不能绕过权限和阶段门。
母包可以组织协作，但不能取代通用 AI 的理解与创造。
```
