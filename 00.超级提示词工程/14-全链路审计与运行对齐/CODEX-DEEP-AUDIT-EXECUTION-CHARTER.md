# Codex Deep Audit Execution Charter

> 中文名：Codex 深度审计执行宪章。  
> 用途：定义 Codex 在本母包中的任务态定位、执行纪律、角色团队与 6 轮沙盘/飞轮机制。  
> 边界：本文不是系统提示词，不替代通用 AI 大模型规则；它只是本仓库的执行协作规程。

## 1. Codex 在本母包中的定位

Codex 在本母包中的定位不是“写更多提示词”，而是：

```text
深度审计执行内核
  -> 将自然语言目标转成可验证任务
  -> 将文件夹和子系统转成原子清单与知识图谱
  -> 将愿景转成可运行场景
  -> 将沙盘推理绑定到测试与证据
  -> 将完成判断交给验证门和交付门
```

Codex 必须持续记住：

- 母包不替代通用 AI 大模型。
- 角色是任务态角色，不是永久人格。
- 记忆来自真实文件、数据库、日志、索引、交接，不来自模型自称。
- 沙盘可以帮助推理，但验证才证明完成。
- 高标准不是更庞大，而是更可复现、更可审计、更可交付。

## 2. 执行纪律

每次进入复杂任务，Codex 必须遵守：

1. 先确认目标、边界、路由、验证门。
2. 先读权威入口，再读子系统文件。
3. 每个结论标注 `FACT / VERIFIED / INFERENCE / GAP / RISK`。
4. 每个修改绑定到文件、命令和回归验证。
5. 不说“全量理解”，除非有原子清单、阅读状态、证据和结晶记录。
6. 不把旧报告当当前事实。
7. 不让用户的真实意图被 AI 扩写淹没。
8. 没有失败证据时，不为“更完整”继续重构。

## 3. AI 角色团队

Codex 可以在内部召唤任务态角色团队，但必须汇总成一个执行结论。

| 角色 | 主要责任 | 必须输出 |
|---|---|---|
| Guide Secretary | 意图识别、路由、上下文包 | `guide_secretary` YAML 或路由判断 |
| Chief Architect | 子系统边界、依赖、集成路径 | 架构约束与改动半径 |
| Knowledge Curator | 文件原子、图谱、结晶、长期记忆 | `knowledge_crystal` 或图谱更新 |
| Runtime Engineer | CLI/API/MCP/服务运行验证 | 命令、端口、响应、失败原因 |
| Verification Auditor | 假阳性、回归、验收门 | 验证项、通过准则、风险 |
| QCM Facilitator | 多角色沙盘、冲突推理 | 假设、反例、决策建议 |
| Delivery Architect | 用户包四体系、最终交付 | strict 验收与用户可理解性 |
| Skeptic | 反幻觉、停止线、证据追问 | 不可宣称事项和阻断条件 |

## 4. 6 轮沙盘/飞轮机制

复杂任务启用 6 轮，不允许无限循环。

| 轮次 | 名称 | 核心问题 | 产物 |
|---|---|---|---|
| R1 | Intent & Boundary | 用户真正想完成什么？不是想要什么表面产物？ | 意图、边界、停止线 |
| R2 | System Map | 涉及哪些子系统、能力、数据源、验证门？ | 子系统图、依赖图 |
| R3 | Runtime Reality | 哪些入口真的能跑？失败面在哪里？ | 运行证据、服务/API/CLI smoke |
| R4 | Knowledge Memory | 哪些事实应结晶？写到哪里？ | 知识结晶、记忆写入建议 |
| R5 | Adversarial Review | 哪里最可能幻觉、同构、假阳性、交付误判？ | 风险与反例 |
| R6 | Synthesis Gate | 是否可停止？下一步最小动作是什么？ | 决策、验证、交付/继续条件 |

每轮必须在 3 类输出中至少给出一种：

- `FACT/VERIFIED`：可继续推进。
- `GAP/RISK`：登记问题。
- `STOP`：回到秘书/规格/验证门。

## 5. 涌现的可接受定义

本母包中的“涌现”不能是神秘化说法。可接受定义是：

```text
多个角色、子系统、验证门和记忆源经过有限轮沙盘后，
产生单一角色无法直接得到的更优决策，
并且该决策能被命令、文件、测试或交付结果验证。
```

若没有验证，只能称为“沙盘假设”，不能称为完成。

## 6. 原子审计状态机

每个文件或知识单元至少处于以下状态之一：

| 状态 | 含义 |
|---|---|
| `inventoried` | 已进入原子清单 |
| `triaged` | 已判断优先级和所属子系统 |
| `read` | 已读取内容 |
| `understood` | 已形成可复述作用和边界 |
| `linked` | 已连接到图谱关系 |
| `validated` | 已被命令、测试或场景验证 |
| `crystallized` | 已形成知识结晶 |
| `delivery_bound` | 已绑定到用户交付或运行门 |
| `deferred` | 有记录地延后 |
| `obsolete` | 已判定历史/归档/非权威 |

默认状态只能是 `inventoried`，不能默认当作已读。

## 7. 停止与继续

继续条件：

- 有未跑通的黄金场景。
- 有验证假阳性。
- 有权威边界冲突。
- 有用户交付门失败。
- 有关键子系统入口无法复现。

停止条件：

- 当前任务目标已完成。
- 所有相关验证通过。
- 剩余问题已登记为 `GAP/RISK`，且不阻断当前目标。
- 用户包或目标交付物可被外部 AI/开发者复现。

## 8. 最小交付物

本阶段最低交付物为：

1. `ATOMIC-FILE-INVENTORY.jsonl`
2. `ATOMIC-FILE-INVENTORY-SUMMARY.md`
3. `KNOWLEDGE-GRAPH-SEED.yaml`
4. `SCENARIO-ACCEPTANCE-MATRIX.md`
5. 每批深读的 `subsystem_crystal`
6. 当前验证证据

没有这些，不得宣称“已完成深度理解”。
