# Memory Source Priority

> 中文名：记忆源优先级与冲突解决规则。  
> 用途：防止通用 AI 把聊天上下文、旧报告、多个数据库和多个知识库混成一团。  
> 原则：长期记忆必须是真文件、真数据库、真日志、真交接；没有读取证据就不能声称已加载。

## 1. 读记忆优先级

| 优先级 | 记忆源 | 适用场景 | 读取规则 |
|---|---|---|---|
| P0 | `MISSION-MEMORY.md` | 母包使命、身份边界、母包/子包边界 | 新会话或使命相关任务必须先读 |
| P0 | `AI_PROJECT_CONTEXT.md` | 全局目录地图、当前子系统状态、已知风险 | 新会话必须读 |
| P0 | `00/12 MISSION-MEMORY-AWAKENING-PROTOCOL.md` | 唤醒握手、停止线、自然语言触发 | 身份/长期记忆/元智核/唤醒任务必须读 |
| P0 | `05/_HANDOFF` | Q-SpecTrum 当前状态和交接 | 修改或运行 `05` 前必须读 |
| P0 | `05/BRAIN-KB` | Q-SpecTrum 长期平台知识 | 处理平台长期知识、决策、限制、模式时读 |
| P1 | `03/.workbuddy/记忆层` | WorkBuddy/Universal-KB 应用记忆 | 文件治理、知识沉淀、MCP 检索任务读 |
| P1 | `05/project_memory.db` | 项目会话/消息/任务记忆 | 使用 `05` API/项目记忆时通过代码或 API 查询 |

## 2. 写记忆优先级

| 写入目标 | 允许写入内容 | 禁止写入 |
|---|---|---|
| `MISSION-MEMORY.md` | 母包使命、边界、启动顺序的 P0 变化 | 临时想法、未验证推断 |
| `AI_PROJECT_CONTEXT.md` | 顶层地图、文件数、子系统状态、关键风险 | 细碎任务日志 |
| `00/14` registries | 项目/能力/产物/验证/审计状态 | 无证据的“已完成” |
| `05/BRAIN-KB` | 平台级长期知识、决策、限制、模式 | 一次性聊天片段 |
| `05/_HANDOFF` | 当前任务交接、验证结果、下一步 | 未确认用户偏好 |
| `03/.workbuddy/记忆层` | 文件治理与知识库应用经验 | 与 `05` 平台长期决策冲突的无来源内容 |
| 用户交付包 | 具体项目交付事实、安装/启动/验证说明 | 母包研究噪音、本机路径、密钥 |

## 3. 冲突解决规则

```text
当前文件/命令输出 > 当前数据库查询 > 当前 handoff > 当前 README/INDEX > 历史报告 > 聊天上下文
```

具体规则：

1. 文档声明与代码冲突：以当前代码和当前验证命令为准。
2. 历史报告与当前验证冲突：以当前验证为准，并记录历史报告可能过期。
3. `03` 记忆与 `05` 记忆冲突：先判断任务归属；文件治理优先 `03`，平台/角色/Brain 优先 `05`。
4. 沙盘结论与测试冲突：以测试或人工验收为准；沙盘只能作为假设来源。
5. 用户口述与文件冲突：标为待确认，不直接覆盖长期记忆。
6. 任何“长期记忆已加载”的说法必须附读取的文件或数据库来源。

## 4. 最小记忆读取模板

```yaml
memory_read_check:
  task_intent: "<一句话>"
  sources_read:
    - path: "<相对路径>"
      reason: "<为什么读>"
      status: "read|not_found|skipped"
  conflicts_found: []
  chosen_authority: "<当前以哪个来源为准>"
  memory_write_needed: false
  memory_write_target: null
```

## 5. 写入门

写入长期记忆前必须满足：

- 来源明确。
- 影响未来运行、交付、安全、路径、验证、架构决策或能力配置。
- 用户已确认，或当前文件/命令已验证。
- 能说明为什么不是临时上下文。

不满足时，只能写入当前 handoff 或任务记录，不进入长期记忆。
