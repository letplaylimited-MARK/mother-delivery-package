# 价值体系

> 用途：说明这个项目为什么值得交付、为谁创造价值、用什么结果验收。
> 生成时间：2026-05-28，基于母交付包全量推演结果。

## 1. 用户与场景

| 项 | 内容 |
|---|---|
| 目标用户 | AI 驱动项目的独立开发者、中小型技术团队、使用通用 AI 大模型（DeepSeek、元宝、Claude、GPT 等）进行日常开发的工程师 |
| 核心场景 | 开发者与 AI 大模型长期协同开发项目——从模糊想法到需求、规格、代码、测试、记忆管理和最终交付的全流程 |
| 当前痛点 | AI 对话散落在多个聊天窗口，无法跨会话传递上下文；需求反复变更导致不断重构；AI 输出的代码/文档缺乏可追溯的证据链；项目交接时"带走的是人不是知识"；每次换 AI 模型都要从头解释项目背景 |
| 项目机会 | 将"自然语言想法→可验证交付物"的整条链路工程化、结构化，使任何通用 AI 大模型都能通过协议栈快速理解项目、持续贡献、安全交接 |

## 2. 价值主张

```text
本项目帮助 AI 驱动的开发者和技术团队
在跨模型、跨会话的长期协同开发场景中
通过结构化协议栈（提示词操作系统 + 阶段门 + 注册表 + 验证证据链）
达成从模糊想法到可验证交付物的端到端工程化
并降低需求漂移、AI 幻觉、知识丢失和交接失败的风险。
```

## 3. 价值地图

| 价值维度 | 交付结果 | 验收指标 |
|---|---|---|
| 效率 | 新 AI 会话无需重复解释项目背景，通过标准唤醒握手在 8 步内进入任务态 | 唤醒握手平均步骤 ≤ 8，首次任务启动时间 ≤ 2 分钟 |
| 质量 | 需求经过 SpecForge 四道阶段门锻造，模糊词被追问澄清，PRD/SPEC 可追溯 | SpecForge Gate 4 产出物含完整性和一致性审查记录 |
| 协同 | 15 角色按需召唤、跨子系统路由、母包/子包边界清晰，多人多 AI 可并行工作 | 路由矩阵覆盖 ≥ 7 个子系统，角色沙盘支持 3 种强度 |
| 可持续 | 记忆基于真实文件和注册表（非假记忆），跨会话跨模型可继承，版本可回溯 | P0-P3 记忆等级体系运行，关键决策有 ADR 记录 |

## 4. 成功标准

- 任何新 AI 模型进入母包后，能在 8 步标准唤醒流程后正确输出 `awakening_check` YAML 并进入任务路由。
- 需求从自然语言到 PRD/SPEC 经过 SpecForge Gate 1-4 全流程，无未解释的默认技术栈或模糊验收标准。
- 子系统验证命令（18 条）全部通过，`qa_runner.py validate` 结果 ≤ 1 个 FAIL（预期为协同交付包模板）。
- 用户交付包 `VERIFY-DELIVERY.ps1 -Strict` 通过，零 FAIL。
- Git 仓库所有 submodule 指针与远程一致，`git status` clean。

## 5. 边界与不承诺

- 本项目不承诺：替代通用 AI 大模型的核心能力；提供永久人格或假长期记忆；自动生成可部署的生产系统（需要开发者确认和补充）。
- 本项目依赖：Python 3.13+ 运行环境、Git（submodule 管理）、通用 AI 大模型服务（用户自备）、文件系统（知识库和记忆存储）。
- 需要后续阶段处理：AKU 知识原子规范文档（AKU-KNOWLEDGE-ATOM-SPEC.md）；项目级 TRACEABILITY-MATRIX 实例填充；02 通用知识库框架从模板态升级为可运行应用。
