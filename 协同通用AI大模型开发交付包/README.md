# 协同通用 AI 大模型开发交付包

> 定位：这是开发者完成具体 AI 应用项目后，交给最终用户的项目交付包骨架。  
> 边界：母交付包先交给开发者；本目录由开发者按项目成果整理、验证、压缩后交付给最终用户。  
> 约定：本目录内的文档、脚本、提示词不硬编码任何本机绝对路径。

## 1. 与母交付包的关系

```text
<母交付包根目录>/                         # 给开发者的完整生产系统
├── 00.超级提示词工程/
├── 01.通讯协议_幽灵通道/
├── 02.通用知识库框架_Universal-KB/
├── 03.数据库管理_文件夹整理AI应用/
├── 04.QCM-MVP-Emergence/
├── 05.超极智脑_Q-SpecTrum/
└── 协同通用AI大模型开发交付包/             # 给最终用户的项目交付包装配区
```

母交付包保存源项目、研究资料、开发仓库、SDK、提示词工程和验证体系。开发者用母交付包开发具体项目后，再把本目录整理成最终用户可以理解、运行、验收和继续协同的交付包。

本目录不是母交付包的简单复制。它应围绕具体项目，只保留对最终用户有价值、可运行、可验证、可维护的内容。

## 2. 四大交付体系

最终用户交付包必须至少回答四类问题：

| 体系 | 回答的问题 | 目录 |
|---|---|---|
| 价值体系 | 这个项目为什么有价值，解决谁的什么问题，用什么指标验收 | `01-价值体系/` |
| 功能体系 | 项目能做什么，用户如何使用，AI/系统能力边界在哪里 | `02-功能体系/` |
| 结构体系 | 项目由哪些模块、文件、数据、接口和依赖组成 | `03-结构体系/` |
| 运作体系 | 如何安装、启动、验证、维护、升级、排错和交接 | `04-运作体系/` |

## 3. 推荐目录结构

正式交付时，建议以这个结构为基础增减：

```text
README.md
交付包组装规则.md
VERIFY-DELIVERY.ps1
01-价值体系/
02-功能体系/
03-结构体系/
04-运作体系/

# 可选：按具体项目需要加入
src/                     # 项目源码
app/                     # 可运行应用
data/                    # 示例数据或初始化数据
docs/                    # 用户文档、接口文档、验收材料
tests/                   # 可运行测试
scripts/                 # 安装、启动、验证、维护脚本
AI_PROJECT_CONTEXT.md    # 面向其他 AI 的项目上下文地图
```

若项目需要继续交给其他通用 AI 大模型协同开发，应从母交付包中选择性纳入 `00.超级提示词工程/`、必要子系统说明、验证命令和上下文包模板。

## 4. 路径规则

所有说明统一使用：

```text
<用户交付包根目录>
<母交付包根目录>
<项目根目录>
<子系统根目录>
```

禁止写入类似：

```text
<某台电脑的盘符或用户目录>\...
<某个具体用户名的主目录>\...
```

## 5. 其他 AI 的启动顺序

其他通用 AI 大模型拿到用户交付包后，建议按顺序读取：

1. `<用户交付包根目录>/README.md`
2. `<用户交付包根目录>/01-价值体系/README.md`
3. `<用户交付包根目录>/02-功能体系/README.md`
4. `<用户交付包根目录>/03-结构体系/README.md`
5. `<用户交付包根目录>/04-运作体系/README.md`
6. 若存在 `<用户交付包根目录>/AI_PROJECT_CONTEXT.md`，再读取该项目上下文地图。
7. 按具体任务进入源码、应用、数据、文档或验证脚本。

## 6. 最终用户第一步

最终用户拿到正式项目交付包后，应先做三件事：

1. 打开 `<用户交付包根目录>/README.md`，确认项目用途、适用对象和交付边界。
2. 进入 `04-运作体系/README.md`，按其中的安装、启动、验证、排错命令操作。
3. 运行项目自己的验证入口；若没有验证入口，这个包不能视为最终可验收交付。

本目录在母交付包中只是装配区和模板。根目录的 `MISSION-MEMORY.md`、`AI_PROJECT_CONTEXT.md`、`开发者母交付包使用说明.md` 是开发者使用母包的入口，不是最终用户包运行的必需文件；只有当项目选择交付 Level 3 AI 协同开发包时，才应把项目级上下文和必要提示词子集放入本目录。

## 7. 当前状态

当前本目录是用户交付包骨架，已经建立入口说明、组装规则、交付验证脚本，以及价值体系、功能体系、结构体系、运作体系模板。后续每开发一个具体项目，都应把项目真实内容填入这些体系，而不是只复制母交付包材料。

## 8. 验证模式

模板阶段运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\VERIFY-DELIVERY.ps1
```

正式交付前运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\VERIFY-DELIVERY.ps1 -Strict
```

普通模式用于确认骨架结构、路径泄漏、密钥泄漏和 Markdown 基础质量；`-Strict` 模式用于最终项目交付，要求补齐项目上下文、交接、变更记录、追踪矩阵、验证报告和项目自己的验证入口。
