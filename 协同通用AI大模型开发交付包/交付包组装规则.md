# 交付包组装规则

> 用途：定义开发者如何从母交付包开发项目，并组装出可迁移、可验证、可交给最终用户的用户交付包。

## 1. 生产链路

```text
母交付包压缩包
  -> 交付给开发者
  -> 开发者解压到任意工作目录
  -> 读取 AI_PROJECT_CONTEXT.md 与 00.超级提示词工程
  -> 按项目目标调用 01/03/04/05 的能力
  -> 开发具体项目
  -> 填写用户交付包四体系
  -> 清理、验证、压缩
  -> 交付给最终用户
```

母交付包是开发生产系统；用户交付包是项目成果系统。不要把母交付包的全部研究资料、历史报告和开发噪音无差别塞进用户交付包。

## 2. 不硬编码原则

所有路径必须相对化：

| 场景 | 写法 |
|---|---|
| 指向用户交付包根 | `<用户交付包根目录>` |
| 指向母包根 | `<母交付包根目录>` |
| 指向项目根 | `<项目根目录>` |
| 指向子系统 | `<子系统根目录>` |
| 命令示例 | 先 `cd <用户交付包根目录>`，再使用相对路径 |

禁止：

```text
<某台电脑的盘符路径>\...
<某个具体用户名的主目录>\...
<某台电脑的绝对路径>/...
```

## 3. 用户交付层级

### Level 1：说明与验收包

```text
README.md
VERIFY-DELIVERY.ps1
01-价值体系/
02-功能体系/
03-结构体系/
04-运作体系/
```

用途：让最终用户理解项目价值、功能、结构、运作方式，并能完成验收。

### Level 2：可运行项目包

```text
Level 1
+ app/ 或 src/
+ scripts/
+ tests/
+ docs/
+ data/ 或 examples/
+ 配置模板文件
```

用途：让最终用户在新电脑上安装、启动、验证、使用项目。

### Level 3：AI 协同开发包

```text
Level 2
+ AI_PROJECT_CONTEXT.md
+ 00.超级提示词工程/ 的必要子集
+ 选定子系统的入口文档、接口契约、验证命令
+ 开发者交接与已知风险
```

用途：让其他通用 AI 大模型和后续开发者继续协同开发项目。

## 4. 四体系填写要求

| 体系 | 必填内容 |
|---|---|
| 价值体系 | 用户画像、业务问题、价值主张、验收指标、成功/失败边界 |
| 功能体系 | 功能清单、用户流程、AI 能力、权限/配置、输入输出、异常处理 |
| 结构体系 | 目录地图、模块职责、数据流、接口、依赖、配置、构建产物 |
| 运作体系 | 安装、启动、验证、维护、备份、升级、排错、交接流程 |

每个体系都必须写具体项目事实；不能只保留模板话术。

## 5. 组装前清理

复制或压缩前应清理：

- `.git/` 是否保留按交付策略决定。
- `__pycache__/`
- `.pytest_cache/`
- `.ruff_cache/`
- 临时 `.db-wal` / `.db-shm` 文件，除非运行时确实需要。
- 个人 `.env`、API key、私密 token。
- 本机绝对路径、用户名、临时下载目录、个人桌面路径。
- 与最终用户无关的研究草稿、过期报告、重复副本。

## 6. 组装后验证

从 `<用户交付包根目录>` 运行项目自己的验证命令。若用户交付包包含母包子系统，可按需运行：

```powershell
cd "<用户交付包根目录>"

# 01 通讯协议：仅在用户交付包包含该子系统时运行
if (Test-Path ".\01.通讯协议_幽灵通道\VERIFY.ps1") {
    Push-Location ".\01.通讯协议_幽灵通道"
    powershell -ExecutionPolicy Bypass -File .\VERIFY.ps1
    Pop-Location
}

# 03 知识库应用：仅在用户交付包包含该子系统时运行
if (Test-Path ".\03.数据库管理_文件夹整理AI应用\verify_install.py") {
    Push-Location ".\03.数据库管理_文件夹整理AI应用"
    python verify_install.py
    Pop-Location
}

# 04 QCM MVP：仅在用户交付包包含该子系统时运行
if (Test-Path ".\04.QCM-MVP-Emergence\02-代码编写\test_qcm_all.py") {
    Push-Location ".\04.QCM-MVP-Emergence"
    python "02-代码编写\test_qcm_all.py"
    Pop-Location
}

# 05 Q-SpecTrum：仅在用户交付包包含该子系统时运行
if (Test-Path ".\05.超极智脑_Q-SpecTrum\verify-integration.py") {
    Push-Location ".\05.超极智脑_Q-SpecTrum"
    python verify-integration.py
    $env:PYTHONUTF8='1'; python run.py --status
    Pop-Location
}
```

若用户交付包是一个新项目，应提供项目自己的最短验证命令，例如：

```powershell
cd "<用户交付包根目录>"
.\scripts\verify.ps1
```

本骨架自带的 `scripts/verify.ps1` 只是结构门禁包装器，用来证明交付包骨架自身合格。正式项目交付时，开发者必须让该脚本调用真实业务 smoke/test，例如 API 健康检查、核心 CLI 场景、单元测试、端到端测试或可复现样例数据验证。

本交付包自带两级验证门：

```powershell
# 模板/基础验证：骨架态允许有项目级缺口警告
powershell -ExecutionPolicy Bypass -File .\VERIFY-DELIVERY.ps1

# 最终交付验证：正式项目交付前必须通过
powershell -ExecutionPolicy Bypass -File .\VERIFY-DELIVERY.ps1 -Strict
```

`-Strict` 模式会要求存在项目级 `AI_PROJECT_CONTEXT.md`、`HANDOFF.md`、`CHANGELOG.md`、`TRACEABILITY-MATRIX.md`、`VALIDATION_REPORT.md` 和至少一个项目自己的验证入口。

## 7. 交付验收标准

| 项 | 标准 |
|---|---|
| 可读 | 最终用户和 AI 都能从 README 找到入口 |
| 有价值 | 价值体系说明清楚目标用户、问题、收益和验收指标 |
| 可使用 | 功能体系说明清楚功能、流程、边界和异常 |
| 可理解 | 结构体系说明清楚目录、模块、数据、接口和依赖 |
| 可运作 | 运作体系说明清楚安装、启动、验证、维护和排错 |
| 可迁移 | 没有本机绝对路径依赖 |
| 可验证 | 核心验证命令能在新环境复现 |
| 可协同 | 需要 AI 继续开发时，有上下文地图、提示词入口和交接记录 |

## 8. 后续可补文件

建议按项目需要继续补：

```text
AI_PROJECT_CONTEXT.md        # 面向其他 AI 的项目上下文地图
PROJECT_REGISTRY.yaml        # 项目登记
CAPABILITY_REGISTRY.yaml     # 能力登记
VERIFY-DELIVERY.ps1          # 总体验证脚本
HANDOFF.md                   # 给用户/AI/后续开发者的最终交接
CHANGELOG.md                 # 用户交付包变更记录
TRACEABILITY-MATRIX.md       # 需求/功能/任务/测试/交付追踪矩阵
VALIDATION_REPORT.md         # 最终验证报告
```
